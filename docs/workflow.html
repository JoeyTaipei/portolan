這版改了什麼

改名Atlas 改叫 Portolan。程式、文件、App 裡的文字都改；設計稿上寫 ATLAS 的地方在 App 裡顯示 Portolan。GitHub repo 和本機資料夾在第 2 步改名。
網頁 App只做網頁，不做 iOS／Android App，也不上 App Store。電腦和手機瀏覽器都要好用：手機寬度照設計稿，電腦寬度用多欄版面。Xcode、Expo、EAS、TestFlight 都不用。
功能全保留設計稿的每個功能都做，包括團隊人脈圖層、網絡分頁、文件申請和專家審稿開關、觀察清單。背後要人工的部分（專家審稿、風險簡報、牽線）按鈕和紀錄是真的，由團隊親手完成。逐項清單在 design/intent.md 第 5 節。
需求文件design/intent.md 重寫：整合設計稿、「Atlas 建 App 流程」的產品方向（護城河、四種文件、方案、團隊人脈規則）和研究結論。
從 v2 保留Parallel 做研究、Claude 只根據來源寫；先比設計方向再寫程式；Spec 和 Plan 只寫一次；Claude 自己跑指令，你負責登入、貼金鑰、做決定、找使用者、按合併。
Claude Code 做法加上「怎麼帶 Claude」：一次給完整範圍和邊界、每個切片都要通過驗證才算完成、被糾正就寫進 CLAUDE.md、用 auto mode 代替一直按允許。只取 MVP 用得到的，多代理、自動審查機器人、效能爬坡都等送出之後。
10/30 更新拿掉 cmux，改用 Claude 桌面版（平行 session、自動 worktree、內建瀏覽器、PR 自動修 CI 都內建）。每個切片改用 /goal 迴圈跑到驗收條件成立。研究引擎加「來源檢查迴圈」。分工：你在 Mac mini 上帶 Claude 做，創辦人在 MacBook 和手機看 preview。
連結這頁每個連結都在 10/30 確認打得開。

工具：要 / 不要

工具要不要為什麼
Mac mini要唯一的開發機。一直插著電開著，Claude 可以整晚跑 /goal。所有程式、金鑰、worktree 都只在這台。
Claude 桌面版（Code 分頁）要主要工具。每個 session 可以開自己的 worktree，兩個並排跑（ui、engine）；內建瀏覽器給 /verify-ui 用；完成或需要你時跳通知；PR 開了以後可以打開 Auto-fix 自動修 CI。
MacBook要（只檢查）創辦人在 MacBook 和手機打開 PR 上的 Vercel preview 實際點一遍，在 GitHub 留意見或核准。不在 MacBook 寫程式、不放金鑰。
/goal要把切片的驗收條件寫成 /goal，Claude 會一輪一輪做到條件成立；每輪由另一個模型判斷做完沒，不是寫程式的 Claude 自己說了算。
Next.js + Vercel要網址點開就能用，每個 PR 自動有 preview，合併後一分鐘內上線。
Supabase要Postgres 資料庫；只從伺服器連，每張表開 RLS。
Parallel要研究結果附來源（Basis），符合「每個結論都要有來源」；非同步執行，不受 Vercel 函式時間限制。
Claude API要評分、策略簡報、7 天計畫、會前簡報草稿、引薦草稿。
PostHog要量 YC 會問的數字：建 dossier、匯出報告、填會後回報。
Playwright MCP備用桌面版有內建瀏覽器，/verify-ui 用它就好。已經裝了不用移除；端到端測試照樣用 npm 的 Playwright。
frontend-design skill要Anthropic 官方。做畫面時避免掉回 AI 預設風。
agent-skills（Addy Osmani）要spec、plan、build、ship 的流程。
Xcode、Expo、EAS、TestFlight不用不做手機 App。
three.js不用地圖照設計稿用 SVG 偽 3D（project() + 拖曳），已經夠用，也容易印進 A4 報告。
Agent Teams先不用4 天衝刺裡 token 多、隊友容易改到同一個檔案；兩個桌面版 session 就夠。
Deep research skill不用一次性研究 Claude 直接上網查就夠；產品裡的研究用 Parallel。
動態 workflow只在上線前一個腳本同時派很多個代理、彙整結果。只用在 S8 上線前的全站安全稽核（同一種檢查掃過每個檔案，再互相驗證），和申請書的 /deep-research。切片照樣用 /goal：切片窄、互相依賴，派一堆代理只會燒 token、改到同一個檔案。
/effort ultracode不用會讓每個任務都變成 workflow：更慢、更快用完額度，還會關掉大型 workflow 的警告。
cmux、Ghostty不用平行 session、通知、瀏覽器桌面版都有，worktree 還是自動的；兩套工具就要盯兩個地方。
Goal Composer、Stop hook先不用/goal 本身就是 Stop hook 的簡化版，MVP 夠用。
gstack、Context7、Lovable不用查文件直接讀官方網站和 node_modules/next/dist/docs/。

怎麼帶 Claude（MVP 版）

規則已寫進 CLAUDE.md

你的工作從寫程式變成定範圍、看驗證結果、做決定。下面這些已經寫進 CLAUDE.md，每個 session 都會自動讀，不用每次重講。

做法MVP 怎麼做
一次給完整範圍不要一步一步下小指令。每個切片的範圍、檔案、驗收條件都已經在 docs/plan.md，指令只要指向它。寫 spec 時用 macOS 聽寫講完整背景，比打字詳細（/voice 不支援中文）。
講清楚不能做什麼只改計畫列的檔案；不加計畫外的功能、工具函式、套件；不動 migration 和 types.ts，要越界先問。
回報要短做完最多 3 行：改了哪些檔案、測試結果、要你看的頁面。不用加「檢查一遍再改錯」這種話，只會更慢更貴。
用迴圈，不要一直下指令你寫「怎樣算做完」，Claude 自己做到。每個切片用 /goal 加上 plan 的驗收條件，在 auto mode 跑。條件要寫成 Claude 會在對話裡印出來的證據（例如「npm test exit 0」），因為判斷的模型只看對話、不自己跑指令。一定加「或 30 輪後停」。
做的和查的分開寫程式的 session 不審自己：/code-review 在新的 session 跑。修 bug 時測試要先在 main 上失敗、修完通過，兩次結果都給你看。
「做完」只是說法你和創辦人看過 preview 才算數。同時最多 2 個寫程式的 session：瓶頸是你們看的速度，不是 Claude。
先看計畫再動手研究引擎（S3）和團隊人脈（S7）比較複雜，先用 /plan 看完再開始。
驗證才算完成每個切片都要：測試和建置通過、/verify-ui 用內建瀏覽器截圖比對設計稿、console 沒有錯誤。修 bug 先寫會失敗的測試。
錯誤只犯一次你糾正 Claude 一次，就請它把規則用一句話加進 CLAUDE.md。用 /memory 看和整理；保持 80 行以內。個人偏好放 CLAUDE.local.md（不會進 git）。
模型和思考深度用預設模型。Spec、評分、研究引擎用 /effort high；畫面切片用預設。不用 /advisor：比較慢、也比較貴。
權限用 auto mode（Claude Code 2.1.283 以後的預設）：安全的指令自動跑，危險的會擋下或問你，不用一直按允許。金鑰只放 .env.local，不貼進對話。
審查每個 PR 跑 /code-review；S3、S7、S8 再加 /security-review（金鑰、prompt injection、上傳檔、分享連結）。最後你看過 preview 才合併。
先不用為什麼
分層 CLAUDE.md專案還小，一個根目錄的 CLAUDE.md 就夠。超過 80 行再拆到子資料夾。
多代理、上百個 subagent給大型遷移用的。MVP 兩個桌面版 session 就夠。
自動審查機器人、GitHub Code ReviewGitHub 上的 Code Review 要 Team／Enterprise 方案；MVP 本機 /code-review 加你看 preview 就夠。
效能爬坡、claude -p 自動化沒有使用者之前沒有東西可以優化。送出後再接進每週流程。
/sandbox、容器會擋到 npm、gh、Vercel 的網路，衝刺期間很麻煩。auto mode 加上金鑰只放 .env.local 就夠；之後跑無人看管的排程任務再開。

10/30 讀 YC 官網

YC 看的Portolan 要拿出來的
一句話講清楚做什麼直白、不行銷，像「X 版的 Y」。例：「給要賣進台灣國防市場的美國無人機新創用的利害關係人地圖，每個人都附來源，見完面回報後分數會更新。」

狀況處理
研究跑太久、函式逾時不要在一次請求裡跑完：建立 Parallel 工作 → 背景執行 → 頁面輪詢或用 webhook 更新進度。
