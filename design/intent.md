# Atlas 需求說明（草稿）

Claude 依「Atlas 建 App 流程指南」的產品方向和 Atlas App Mockup.html 整理。標 **【待補】** 的地方請創辦人用自己的話填完，其他地方不對也直接改。

# App 目的
幫要進入海外市場的新創和企業，拿到在新市場的第一個客戶、合作夥伴或投資人。使用者輸入公司、產品和目標市場，Atlas 把公開資料整理成**每一點都附來源**的利害關係人地圖、策略簡報和一頁報告，並協助見到對的人。

產品路線：MAP（地圖）→ PLAN（策略）→ MEET（見面）→ TRACK（追蹤）。報告本身不是護城河；護城河是客戶回報「哪條路真的有用」累積的成果資料，和在地專家網絡。

# 目標使用者
【待補】例：要進台灣國防／無人機市場的美國或歐洲深科技新創，創辦人或 BD 負責人。

# 先做哪條走廊
【待補】設計稿的範例：美國反無人機新創 → 台灣。網絡要夠密才有用，MVP 只做一條。

# 核心使用流程
1. Dossiers 首頁按「+ New dossier」，填公司、產品、目標市場、目標（例：12 個月內拿到第一個政府試辦案）、Email，按「Start research」。
2. 研究進度畫面（幾分鐘），完成後進入 dossier 首頁。
3. 3D 地圖：轉動、點節點看詳情（立場、影響力、支持度、來源、建議動作）→「Add to tracker」。
4. 策略簡報 → 匯出一頁 A4 PDF，或複製分享連結。
5. 見完面隔天，在追蹤器填會後回報（30 秒）→ 該利害關係人的支持度和階段更新。

# 產品規則（不可違反）
- 每個利害關係人、分數、建議都要追到至少一個來源（URL + 摘錄 + 查證日期）
- 找不到來源就標「未驗證」，絕不編造人名、機構、職稱、數字
- 中國市場只做機構層級，不建個人檔案
- 範例資料一律標 Sample data

# 評分
【待補】確認或修改下面的草稿：
- 影響力 influence：0–100，對這次進入市場的決定有多大影響
- 支持度 support：−100（反對）～+100（支持）；立場由支持度切：≥ +20 支持、≤ −20 反對、其他中立
- 可信度 confidence：有幾個獨立來源、來源類型（政府公報 > 議事紀錄 > 新聞）
- Entry readiness、Opposition index（/100）和 Window to act（天）怎麼算：【待補】

# 誰能看到什麼
- MVP 不做登入：每份 dossier 一個猜不到的網址，有網址的人才看得到
- 會後回報裡「對方說了什麼」只存在那份 dossier，不給其他客戶

# MVP 一定要有
01、02（不含團隊人脈）、03、05、06 真的做；04、07 做成人工代辦按鈕；`/d/sample` 永遠可看範例。
